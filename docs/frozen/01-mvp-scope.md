# 01. MVP 范围与产品边界

## 产品定位

本项目是独立的新项目，不修改、不删除、不读取现有 Daily Brief 项目的业务数据、Schema、Agent 或 Workflow。

系统接收用户主动上传的单个 `.eml`，从邮件中生成一份包含多个测试领域和测试用例草稿的测试计划。计划必须经过确定性校验、人工 Review、报文预览和二次确认，才能提交至本地 Mock 测试管理平台。

系统是测试计划辅助生成工具，不替代测试负责人做最终业务判断。

## 核心链路

```text
.eml 上传
→ 安全解析与正文清洗
→ 可信证据切片
→ 一次受控 LLM 结构化提取
→ 测试计划草稿
→ 多领域与用例草稿
→ 可信证据重建
→ 确定性规则校验
→ 人工编辑与 Review
→ 平台报文预览
→ 操作者声明与二次确认
→ HMAC 签名和幂等提交
→ 回执、对账与审计
```

## 一期实现范围

- 单个 `.eml` 上传、重复检测和安全解析。
- 邮件头、纯文本、HTML、历史回复和转发引用处理。
- 证据切片、哈希、定位和安全摘录。
- 一封不同内容的邮件生成一个独立 TestPlan。
- 一个计划包含多个领域明细，每个领域包含多条结构化用例草稿。
- 一次 LLM 调用完成结构化提取，失败时降级为空白草稿。
- 版本化领域字典、值域、规则元数据和平台映射。
- 不可变计划版本、规则校验、人工退回或批准。
- 报文预览、二次确认、HMAC-SHA256、幂等提交和超时对账。
- 独立本地 Mock Gateway。
- 现代简约的 React 前端闭环。
- Docker Compose 单机开发／演示部署。
- 版本、Review、提交结果和业务审计长期保存。

## 明确不做

- 用户、登录、租户、角色、权限或组织结构。
- AgentScope、多 Agent、自主规划、模型工具调用或记忆。
- 邮箱扫描、Outlook COM、Outlook Add-in、Microsoft Graph。
- 粘贴文本、`.msg` 或批量邮件导入。
- 附件正文解析、压缩包展开、宏或可执行文件处理。
- 真实企业 UTP、Kiwi TCMS 或其他真实平台适配器。
- 自动批准、自动提交、自动执行用例。
- 提交成功后的修改、撤销、覆盖、克隆或替代关系。
- 多实例、高可用、水平扩缩容、生产级灾备或 Kubernetes。
- 静态数据加密、在线密钥轮换或生产敏感邮件处理承诺。

## 核心不变量

- 相同原始文件 SHA-256 只对应一个 ImportedEmail 和一个 TestPlan。
- 同一计划版本不可变；内容变化产生新版本。
- 一个计划可包含多个领域，但相同 `domain_key` 不得重复。
- LLM 不得创造领域编码、负责人、工号、日期或外部编码。
- Blocking 不可豁免；Warning 必须在批准时逐条确认。
- 批准与提交二次确认是两个不同操作。
- `submitted` 是终态。
