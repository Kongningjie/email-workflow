# 04. 邮件、证据与安全边界

## 上传限制

- 只允许用户主动上传单个 `.eml`，最大 5 MiB。
- 扩展名必须为 `.eml`，大小写不敏感。
- MIME 接受 `message/rfc822`；`application/octet-stream` 必须通过邮件结构校验。
- 必须至少包含一个非空纯文本或 HTML 正文。
- 清洗后正文最多 200,000 个 Unicode 字符；超限拒绝，不截断提取。
- 限制邮件头数量、单字段长度和 MIME 嵌套深度。
- 原始文件在解析前计算 SHA-256。

## 附件与主动内容

- 附件只记录名称、MIME 和大小，不读取正文、不长期保存、不发送模型。
- 不展开嵌套邮件、压缩包、宏或可执行附件。
- HTML 删除脚本、事件属性、表单、嵌入对象及远程资源。
- 不访问邮件中的远程图片、链接或其他 URL。

## 正文与历史引用

- 顶层头部形成独立证据类型；当前正文为 `current_body`，历史回复和转发为 `quoted_body`。
- 签名、法律声明、营销页脚及纯格式噪声移除。
- 两类正文均可用于提取；关键事实只存在于 `quoted_body` 时产生 Warning。
- 引用区的 `From:`、`To:`、`Date:` 等文本不得作为顶层元数据。
- 无法可靠分区时保留正文并记录解析 Warning。

## 证据切片

- 偏移量基于规范化纯文本，不基于原始 HTML 字节。
- 目标片段约 1,000 字符，相邻重叠约 100 字符。
- 每段保存独立 SHA-256；重建时核对来源、边界与哈希。
- 证据摘录不得由模型提供。

## 重复邮件

- 原始文件 `content_sha256` 具有唯一约束。
- 相同哈希返回已有记录，不再次调用 LLM。
- 解析／提取失败可在原记录上显式重新处理，并创建新计划版本。
- 已提交计划不能通过重复上传重新打开。
- 不实现替代、克隆或计划关联；不同内容的新邮件创建独立计划。

## 外部模型数据边界

上传前必须提示并确认：清洗后的邮件内容将发送至 DashScope。

允许发送必要邮件头、临时 evidence ID、section type 和清洗后的证据文本；姓名和工号因属于提取目标，不自动脱敏。

禁止发送原始 `.eml`、附件、文件路径、数据库 ID、密钥、内部标识符、Review 或平台凭据。本 MVP 不用于被明确禁止外发的生产敏感邮件。

## 明文存储声明

- 原始 `.eml` 与清洗正文在主应用本地数据卷明文保存 24 小时。
- `safe_excerpt` 在 PostgreSQL 明文保存 90 天。
- 数据卷不作为静态资源，不允许 Mock Gateway 访问，仅主应用进程可读写。
- 数据目录、数据库数据和 `.env` 必须排除在 Git 外。
- 日志、异常与 API 响应不得泄露完整正文或不必要的摘录。
- 演示部署不为短期邮件数据配置自动备份。

MVP 不提供静态数据加密，不应直接处理生产敏感邮件。
