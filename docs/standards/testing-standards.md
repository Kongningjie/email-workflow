# 测试规范

## 测试分层

- 单元测试：解析辅助函数、规范化、规则、状态机、哈希和签名。
- 组件测试：Repository、Service、Workflow、Extractor 和 Gateway。
- API 测试：请求验证、状态码、错误、并发和幂等。
- 前端测试：关键组件与表单状态。
- 端到端测试：Docker Compose 下完整主链路。
- 真实模型评测：显式人工触发，不进入默认 CI。

## 确定性

- 默认测试禁止网络访问。
- 时间、UUID、随机数和外部响应可注入或固定。
- FakeExtractor 覆盖成功、超时、限流、异常、无效结构和未知 evidence ID。
- Mock Gateway 覆盖成功、重复、4xx、5xx、超时、`not_found` 和对账。
- 测试不依赖执行顺序或共享脏数据库。

## 数据与隐私

- Fixtures 使用虚构姓名、工号、邮箱和项目。
- 禁止提交真实邮件、API Key 或生产响应。
- 快照测试不得包含敏感正文。
- 测试结束清理临时文件和数据库记录。

## 覆盖重点

- 上传限制、MIME、HTML 清洗与远程资源阻断。
- 引用分区、证据偏移量和哈希重建。
- Prompt 注入与未知证据拒绝。
- 状态转换、不可变版本和 409。
- Blocking／Warning。
- RFC 8785、HMAC 和重放时间窗。
- 确认令牌、幂等提交、unknown 对账。
- 数据保留期和安全清理路径。

只有 `RUN_LIVE_LLM_TESTS=1` 且配置 DashScope Key 时运行 `live_llm`。报告记录模型 ID、提示版本、耗时、token 和冻结指标，不记录完整输入输出。

新行为必须有测试；Bug 修复先复现再验证；文档和接口变更同步完成。
