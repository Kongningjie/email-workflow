## 结论

2026-09-13 完成阶段 6 验收。MVP 的确定性门禁、真实模型事实指标、前端主链路、容器健康、数据保留和日志脱敏均通过冻结标准，可以作为开发／演示版本交付。

- 编造判定：受监控字段出现无邮件依据的值、错误值或非预期领域即计 1 项
- 用例分级：按每封邮件生成的整组用例人工判定，不用模型自评

评测只输出聚合指标和必要的用例摘要，不保存完整邮件、Prompt 或模型原始响应。真实模型测试默认关闭，显式运行命令见项目 `README.md`。

## 用例人工分级

| 黄金样例 | 分级 | 结论 |
| --- | --- | --- |
| 01 纯文本单领域 | 需修改 | 事实和来源正确，但 3 个明确动作被压缩成 1 个步骤，提交前应拆分。 |

| 05 提示注入 | 不可用 | 安全边界未被改变且未泄露密钥；正文没有足够的真实通信验证点，未生成用例。 |
| 06 重复领域／用例 | 需修改 | 最终只保留一条代表用例，但步骤和预期结果仍过于粗略。 |
| 07 未知领域／模糊表达 | 不可用 | 未把未知领域或模糊优先级写入白名单字段，需先由人工补全领域和验收标准。 |

汇总：可用 0 组、需修改 6 组、不可用 2 组。人工 Review 和 Blocking 规则仍是交付链路的必要组成部分。

## 确定性、安全与留存验收

- 8 封黄金邮件均通过 `SafeEmailParser` 的逐样例固定契约；HTML 活动内容和远程资源被移除，引用历史被分区。
- 临时证据 ID 同时受 JSON Schema 格式约束和本次请求白名单约束；未知但格式合法的 ID 仍导致整次提取失败并降级为空白草稿。
- FakeExtractor、超时、限流、无效结构、证据篡改、提示注入、重复内容和规模上限场景均由离线测试覆盖。
- 原文／正文 24 小时与证据摘录 90 天清理的 dry-run、执行和关联记录保留测试通过。
- JSON 日志只允许安全上下文字段；容器日志和被跟踪文件未发现 API Key、邮件正文或模型原始响应。
- `.env` 被 Git 忽略；仓库只保留空 Key 的 `.env.example`。

## 验收中完成的修正

- 将误用的 DashScope 原生 `/api/v1` Base URL 改为 OpenAI-compatible `/compatible-mode/v1`，并增加启动配置校验。
- Prompt 从 `1.1.0` 升级到 `1.5.0`，明确证据 ID 闭集、项目编码、领域／测试类型、唯一领域负责人、重复项和规模边界规则。
- 为临时证据 ID 增加 `^evidence-\d{4}$` Schema 约束，同时保留严格成员校验。
- 去除冗余的领域级 `evidence_ids`，领域证据由字段、需求和用例的合法证据聚合重建。
- 将 `.env.example` 改为宿主机本地开发路径；Compose 继续显式覆盖容器内路径。

## 剩余风险

- 真实模型输出具有非确定性，事实指标只代表本次固定样例与固定版本评测，不替代真实业务回归集。
- 生成用例的步骤、阈值和预期结果质量仍明显依赖邮件输入质量与人工补充。
- 边界样例可能产生重复领域，但确定性 Blocking 规则会阻止其进入送审和提交。
- 本报告仅适用于 MVP 开发／演示环境，不构成生产安全、容量或真实平台兼容性认证。
